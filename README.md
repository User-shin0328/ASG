# ASG · 정책 기반 DB 접근 보안 게이트웨이

**사내 프로그램·에이전트의 DB 조회를 명시적인 보안 정책으로 허용·검토·차단하는 게이트웨이입니다.**

ASG의 핵심은 접근 권한의 조건을 코드와 정책으로 정의하고, 실행 시점까지 그 조건을 검증하는 것입니다. 등록된 일상 조회는 자동 허용하고, 업무 판단이 필요한 예외는 사람에게 전달하며, 정책 위반은 차단합니다. 요청자는 일반 프로그램이나 외부 AI 에이전트일 수 있습니다. 게이트웨이의 접근통제 결정은 LLM 추론 없이 규칙으로 수행합니다.

## 정책 기반 통제의 강점

| 강점 | 현재 구현에서 확인할 수 있는 내용 |
|---|---|
| 명확한 권한 경계 | 서버가 정한 신원·역할·테넌트·작업과 등록된 데이터·열·조회량을 검사합니다. 요청자가 권한을 주장하거나 자연어 목적을 적는 것만으로 접근 권한이 생기지 않습니다. |
| 설명하고 재현할 수 있는 결정 | 정책 일치 여부와 위반 사유를 기록합니다. 정책·권한·요청·사용량 등 같은 조건을 구성해 허용·검토·차단을 시험할 수 있습니다. |
| 사람 검토의 집중 | 명시적 정책에 맞는 일상 요청은 자동 처리하고 예외 요청만 검토합니다. 반복 업무는 기간·횟수·총량을 제한해 승인할 수 있습니다. |
| 승인 이후에도 유지되는 통제 | 실행 직전에 현재 정책·역할·승인 범위·만료·취소·누적 예산을 다시 확인합니다. 사람 승인도 정책 위반을 덮어쓸 수 없습니다. |
| 작은 반복 조회까지 통제 | 요청 하나의 크기와 함께 신원별 누적 횟수·행 수를 검사합니다. 실행 전에 최대량을 예약하고 실제 반환량으로 정산합니다. |
| 결과를 추적하는 감사·검증 | 요청, 분석 근거, 승인·거절, 실행 영수증, 반환량, 취소 이력을 연결합니다. 보고서·시험 로그도 실행 ID와 해시로 대조합니다. |

위험 점수는 관제와 검토 우선순위를 위한 지표입니다. **점수가 낮다는 이유만으로 자동 허용하지 않습니다.** 예를 들어 운영 이력의 자유문장 열 `description`은 점수가 낮아도 기본 자동 허용 범위에 없으므로 검토가 필요합니다.

## 요청 처리 구조

```mermaid
flowchart LR
    A["사내 프로그램·에이전트"] --> G["게이트웨이<br/>인증·정책·행위 규칙 검사"]
    G -->|"자동 정책·유효한 범위 승인 일치"| W["허용 · 실행 대기"]
    G -->|"유효한 예외 요청"| H["사람의 근거 기반 검토"]
    G -->|"정책 위반·분석 실패"| D["차단·감사 기록"]
    H -->|"일회·제한된 반복 승인"| W
    H -->|"거절·만료"| D
    W -->|"원래 에이전트의 별도 실행 요청"| E["현재 권한 재검증<br/>누적 예산 예약"]
    E --> T["읽기 전용 도구·보호 DB 조회"]
    T --> R["영수증 저장·실제 반환량 정산·감사"]
```

접수 단계의 허용이나 사람 승인이 즉시 SQL을 실행하지는 않습니다. 원래 요청한 에이전트가 별도로 실행을 요청해야 합니다. 클라이언트는 등록된 데이터셋·열·필터·행 수를 전달하며 임의 SQL과 쓰기 작업은 허용하지 않습니다.

### 세 가지 정책 결정

| 결정 | 적용 조건 | 접수 응답 |
|---|---|---|
| 허용 | 명시적 자동 허용 정책 또는 유효한 반복 업무 승인에 일치 | HTTP 200, 실행 대기 |
| 검토 | 권한상 가능한 요청이지만 자동 허용 범위 밖 | HTTP 202, 사람 승인 대기 |
| 차단 | 미등록 데이터·열, 권한·형식 위반, 분석 실패, 과도한 요청 빈도 등 | HTTP 403, 실행 불가 |

기본 자동 허용 정책은 등록된 역할·작업의 `operations` 조회 중 `ticket_id`, `category`, `status` 열과 요청당 100행 이하를 대상으로 합니다. 민감정보·대량 조회는 기본 자동 정책에서 제외합니다. 유효한 반복 업무 승인이 있으면 그 승인 범위 안에서 재사용할 수 있습니다. 새 이상 징후는 자동 허용과 승인 재사용을 제한합니다.

### 범위·누적량·장애 통제

- **반복 업무 승인:** 같은 신원·역할·테넌트·작업·DB 대상·데이터·열·필터·목적에 묶습니다. 기간·실행 횟수·총 반환 행 수를 제한하고 원래 승인한 요청도 사용량에 포함합니다.
- **누적 예산:** 기본값은 신원별 최근 30분 1,000회·5,000행입니다. 자동·일회·반복 승인에 모두 적용하며, 실행 한도 초과는 HTTP 429로 거부합니다.
- **현재 권한 재검증:** 정책·카탈로그·대상·역할 변경, 승인 만료·취소를 검사합니다. 범위 승인 취소는 해당 승인으로 성공한 요청의 결과 재조회에도 적용됩니다.
- **응답 유실:** 결과가 불명인 실행은 예약량을 유지합니다. 저장된 영수증으로 완료 여부를 대조하며 대조 자체는 새 SQL을 실행하지 않습니다. 영수증이 없으면 예약을 임의로 환급하지 않습니다.
- **동시 실행:** PostgreSQL에서는 신원별 예산과 감사 체인의 잠금으로 독립 Gateway 연결 간 경쟁을 통제합니다. 같은 실행 ID는 영수증을 재사용해 중복 실행·차감을 방지합니다.

기본 한도는 검증용 설정입니다. 실제 운영 규모에 적합한 정책값이나 처리량으로 확정한 수치는 아닙니다. 30분 위험 지표와 실행을 제한하는 누적 예산은 별도로 계산합니다.

## 대시보드와 시뮬레이터

어두운 배경·흰 글씨·청록색 구분선과 왼쪽 메뉴를 사용합니다.

| 메뉴 | 확인·수행할 수 있는 작업 |
|---|---|
| 보안 현황 | 오늘 요청 처리 결과, 최근 30분 위험도, 실제 구성요소 작동 상태 |
| 승인 검토 | 시간·위험순 대기 목록, 요청·분석·추천 대응 확인, 근거를 남기는 결정, 반복 승인 발급·사용량·취소 |
| 감사 기록 | 한국 시간 날짜별 요청 이력과 누가·언제·어디서·무엇을 요청했는지의 상세보고서 |
| 작동 테스트 | 게이트웨이·보안 분석·보호 DB·감사 DB·무결성의 원클릭 점검 |

별도 시뮬레이터는 일반 조회, 민감정보, 대량 조회, 미등록 열, 목적 문자열의 의심 지시문 등 5개 요청을 실제 API로 보냅니다. 승인 후 에이전트 실행과 유실 응답의 상태·영수증 확인도 체험할 수 있습니다. 이는 규칙 기반 가상 요청 프로그램입니다.

감사 화면은 요청 메타데이터·처리 근거·반환량을 보여주며 조회 결과의 실제 행 본문은 노출하지 않습니다.

## 실행과 테스트

### 실행파일

[ASG.exe](ASG.exe)를 실행하고 실행 창에 표시되는 로컬 대시보드 주소를 엽니다. 기본 실행파일은 **가상 데이터 SQLite 검증 모드**이며 Python이나 Docker 없이 실행할 수 있습니다. 종료는 실행 창에서 Ctrl+C를 사용합니다.

PostgreSQL은 [연결 절차](docs/POSTGRESQL_CONNECTION.md)를 사용하는 별도 환경입니다. 가상 데이터 2,700행을 보존하는 전용 DB는 [검증 DB 안내](testing/VALIDATION_DB_GUIDE.md)를 따릅니다.

### 소스에서 재빌드·검증

Windows PowerShell과 Python 3.10 이상을 사용합니다. 실제 PostgreSQL 시험에는 Docker Desktop이 필요합니다.

```powershell
.\testing\setup.ps1
.\scripts\build_exe.ps1
.\testing\run_tests.ps1
.\.venv\Scripts\python.exe -m testing.report_evidence
```

```powershell
# 가상 SQLite의 초기 5개 시나리오 자동 검증
.\.venv\Scripts\python.exe -m tests.virtual_agent_simulation --auto --no-browser

# 사람이 승인·거절하며 반복 체험
.\.venv\Scripts\python.exe -m tests.virtual_agent_simulation

# 별도 임시 PostgreSQL의 실제 조회·권한·동시성 검증
.\.venv\Scripts\python.exe -m testing.postgresql_checks --policy-controls
```

자동 시뮬레이션은 실패 시 종료값 1을 반환합니다. 민감·대량 요청의 승인 대기 확인을 사람 승인 후 조회 완료와 구분합니다. 기본 임시 시뮬레이션과 보존형 PostgreSQL 환경은 데이터 수명과 실행 방법이 다릅니다. 직접 체험할 순서는 [START_HERE.md](testing/START_HERE.md)에 있습니다.

## 현재 검증 범위

현재는 가상 데이터로 정책 집행·사람 승인·조회·감사·복구 흐름을 구현하고 검증한 프로젝트입니다. 실제 사내 스키마 매핑, 기업 IdP, 운영 인증서·네트워크 격리, 고가용성, 생산 처리량은 별도 검증 대상입니다.

자유문장 검사 규칙이 모든 프롬프트 공격이나 목적의 진실성을 판별하는 것은 아닙니다. 누적 행 수는 고유 레코드 수나 바이트 단위 DLP가 아닙니다. 과거 모델·외부 데이터셋 평가는 역사적 자료로 보존하며 현재 정책 기반 게이트웨이의 성능 근거로 사용하지 않습니다.
