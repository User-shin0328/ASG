# 정책 게이트웨이 화면 검토

2026-11-03. 기존 Impeccable Operate / 테이스트스킬 Data terminal(seed 994061310) 방향을 유지했습니다. 검토자는 현재 작업자이며 이번 변경에 대해 독립 리뷰어의 승인을 새로 받았다고 표현하지 않습니다.

## 실제 조작과 응답

가상 데이터 SQLite 소스 서버에서 실제 브라우저로 다음 흐름을 수행했습니다. PostgreSQL SQL 경계 검증은 별도 자동 보고서의 증거입니다.

1. 일반 요청이 자동 허용되고 민감·대량은 승인 대기, 잘못된 열은 차단되는 것을 확인했습니다.
2. 민감 급여 요청을 보고서에서 열고 ‘반복 업무 승인’을 선택했습니다. 기간 10분·20회·2,000행과 판단 근거를 입력해 승인했습니다.
3. 동일 범위 요청을 다시 생성해 HTTP 200, 범위 승인 적용을 확인했습니다.
4. 실제 에이전트 API로 기본 자동 조회 25행, 원래 승인 요청 25행, 후속 범위 요청 25행을 실행했습니다. 화면의 반복 승인 사용량은 2/20회·50/2,000행, 전체는 3/1,000회·75/5,000행이었습니다.
5. ‘승인 취소’를 펼치고 이유를 입력해 취소했습니다. 상태가 ‘취소’로 바뀌고 사용 기록은 남았습니다. 원래 요청과 후속 성공 요청의 재조회 모두 403 `SCOPE_GRANT_INVALID`를 확인했습니다.

구조화된 관찰값은 `results/policy-v3-ui/API-actions.json`, `revocation.json`에 있습니다. 토큰과 연결 비밀은 이 증거에 넣지 않았습니다.

통합시험 한 회차에서 교차 출처 요청의 기대 403 대신 Windows `10053` 연결 중단에 따른 503이 관찰됐습니다. 실패 보고서는 로컬 날짜별 이력에 보존했습니다. 같은 요청을 별도 50회 검사해 모두 403이었고, 통합시험 재실행도 통과했습니다. 차단 조건을 완화하거나 실패를 감추는 재시도는 추가하지 않았습니다. `transport-recheck.json`에 범위를 기록했습니다.

## 반응형 검토와 수정

첫 회차 측정은 승인 검토 1440×900, 768×1024, 390×844였습니다. 자동 측정은 0 FAIL이었지만 실제 캡처에서 768px 표의 관리·사용량 열이 내부 가로 스크롤 밖으로 밀린 것을 확인했습니다.

한 번의 수정 묶음으로 표의 목록 전환 기준을 1000px로 넓히고 반복 승인·예산 제목과 설명을 좁은 화면에서 세로로 배치했습니다. 새 CSS의 불필요한 색상 fallback도 제거했습니다. 이후 같은 세 폭으로 확인 검사와 전체 캡처를 열어 검토했습니다. 주요 동작과 사용량이 화면 안에서 보였고 가로 잘림은 없었습니다.

| 검사 | 결과 |
|---|---|
| 테이스트 source lint | 0 FAIL / 0 WARN |
| 확인 회차 실브라우저 inspector | 세 폭 모두 0 FAIL / 경고 종류 1개(tiny-text) |
| 캡처 육안 검토 | 제목·목록·상태·사용량·버튼의 겹침과 잘림 없음 |
| 기존 디자인 유지 | 어두운 배경·흰 글씨·청록 구분선·초록/빨강 의미 유지 |

작은 글씨 경고는 기존 보조 메타데이터·시간·행 수의 11~12px 사용 때문에 남았습니다. 주 제목과 동작은 더 크게 유지했으나 작은 글씨가 편한 모든 사용자에게 충분하다고 일반화하지 않습니다. 모바일에서 펼친 반복 승인 양식 전체에 대한 별도 조작 검증은 하지 않았습니다. 자동 API 검증과 데스크톱 브라우저 조작을 그 증거로 혼동하지 않습니다.

앱 화면 기준의 작업자 자체 평가는 디자인 7/10, 사용성 8/10, 일관된 방향 7/10, 정보 충실도 8/10(가중 7.4)입니다. 새로운 장식보다 예외 검토→제한 승인→사용량·취소 확인의 작업 흐름을 우선했습니다. 수정 뒤 다시 디자인 변경을 반복하지 않고 범위 내 확인으로 마쳤습니다.
