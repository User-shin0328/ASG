# ASG 폴더 분석과 현재 구현 범위

대상: 현재 ASG 체크아웃. 갱신일: 2026-10-31 (Asia/Seoul).

## 현재 구성

| 구성 | 실제 구현 |
|---|---|
| 사내 에이전트 요청 | 인증된 structured DB-read API. 서버가 principal/tenant/task를 결정 |
| 보안 에이전트 | `security_agent/assessment.py`의 정책·행위 규칙 분석. 위험 점수·근거·추천 대응 |
| 게이트웨이 | 등록된 데이터·열·필터·조회량·역할·테넌트 검증과 승인·실행 강제 |
| 사람 승인 | 요청·분석·정책 해시 결합, 판단 근거, 만료·중복 결정 방지 |
| 실제 DB 조회 | 가상 데이터 SQLite 테이블의 매개변수화 SELECT. 원래 에이전트가 별도 실행 |
| 재실행 | 동일 execution_id의 저장된 영수증 반환 |
| 요청 보고서 | `db_access_requests`, 추가 전용 `db_access_events`, 기존 해시 체인 감사 연결 |
| 날짜별 이력 | Asia/Seoul 접수일 기준, 테넌트 제한, 50건 단위. 200건을 넘는 이력도 조회 |
| 현재 위험도 | 최근 30분 민감·대량·비정상 요청 가중합과 시간 감쇠 |
| 상태·진단 | 실제 게이트웨이·보안 분석·보호 DB·감사 DB·해시 연결 점검 |
| 대시보드 | 왼쪽 메뉴, 현황·승인·감사·작동 테스트 네 페이지, 보고서 팝업 |
| 기존 기능 | 문서 읽기·요약 저장·모의 전송함·입력 검사·기존 API 보존 |

## 검증

최초 작업 전 기존 74개 테스트가 성공했고, 첫 실행파일 작업에서 88개로 확장했습니다. 이번 DB 요청 확장 후 **112개 회귀 테스트와 31단계 통합 검증**이 통과했습니다. 실제 실행 시각·응답·실행파일 해시는 [최신 결과보고서](results/latest/REPORT.md)를 기준으로 확인합니다.

병렬 조회 중 등록된 principal이 간헐적으로 누락되던 문제를 재현했습니다. 공유 DB 연결의 결과 행을 잠금 안에서 읽어 분리하도록 수정했고, 병렬 인증 1,500건 단위 회귀 테스트와 동시 HTTP 조회로 확인했습니다. 승인 전 실행 차단, 승인 뒤 스냅샷 변조, 권한·테넌트 경계, 한국 시간 날짜 경계, 30분 감쇠, 재시작 보존도 검사했습니다.

2026-11-01 푸시 전 기존 입력 검사기 `scan_untrusted_text`를 합성 개발셋 60건으로 별도 평가했습니다. 악성 30건 중 4건 탐지·26건 미탐, 정상 30건 중 오탐 0건으로 재현율 13.3%, 정밀도 100%입니다. 이는 DB 접근 흐름의 112개 테스트·31단계 통과와 별개이며, 입력 검사기만으로 공격을 충분히 탐지한다고 볼 수 없습니다. 승인·권한·등록된 조회 범위의 강제가 계속 필요합니다. 독립 벤치마크·외부 LLM 평가는 수행하지 않았습니다. [평가 원본과 환경](evaluation-development/summary.md)에 수치와 데이터셋 해시를 보존했습니다.

## 실행파일과 데이터

- 루트 `ASG.exe`를 현재 소스로 갱신했습니다. 중복 배포 실행파일은 만들지 않았습니다.
- `.venv/`는 테스트·빌드 환경, `build/`는 중간 산출물입니다. 실행파일 사용에는 둘 다 필요하지 않습니다.
- 실행 데이터는 기본 `%LOCALAPPDATA%\ASG\lab`이고, 수동 실험은 별도 `.runtime` 디렉터리를 사용합니다.
- 과거 테스트 증거·사용자 데이터·다른 프로젝트·Docker 볼륨을 삭제하지 않았습니다.
- 호환 BAT/PowerShell과 기존 CLI는 보존했습니다. 새 DB 흐름은 `demo_agent/db_client.py`를 사용합니다.

## 명확한 한계

현재 보호 DB는 검증용 SQLite이며 실제 사내 DB나 기업 IdP는 연결하지 않았습니다. 보안 분석은 동작하는 규칙 엔진이며 LLM이라고 표현하지 않습니다. PostgreSQL용 감사 스키마와 Docker 네트워크 구성은 소스에 있지만 이번 로컬 PASS로 해당 환경의 실동작까지 증명하지 않습니다.

로컬 화면은 루프백 검증용 관리자 인터페이스입니다. 같은 OS 사용자 권한의 악성 프로세스와 데이터 파일을 격리하지는 않습니다. 감사 해시 연결은 외부 앵커 서명이나 전체 삭제 방지를 증명하지 않습니다. 원본 IP가 아니라 게이트웨이가 관찰한 접속 IP를 표시합니다.

설계 판단·API·산식·연동 방법은 [DB_ACCESS_GATEWAY.md](../docs/DB_ACCESS_GATEWAY.md), 절차와 예상·실제 결과는 [TEST_GUIDE.md](TEST_GUIDE.md)에 있습니다.
