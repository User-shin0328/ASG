# DB 접근 게이트웨이 현재 동작

현재 기준은 [설계계획서](POLICY_GATEWAY_IMPLEMENTATION_PLAN.md), [API](api.md), [적용 내용](POLICY_GATEWAY_CHANGES.md)입니다.

1. 서버가 요청자의 신원·역할·테넌트·작업을 인증합니다.
2. 등록된 데이터·열·필터·행 수와 보조 입력 규칙을 검사합니다.
3. 위반은 자동 차단, 유효한 범위 승인 또는 명시적 기본 정책은 자동 허용, 나머지 유효 요청은 검토합니다.
4. 실제 실행 직전에 현재 권한·스냅샷·정책·반복 승인·누적 예산을 검사합니다.
5. 최대 요청량을 예약한 뒤 보호 DB를 읽고 실제 반환량으로 정산합니다. 같은 실행은 영수증을 재사용합니다.
6. 자동 허용·발급·취소·차단·실행을 감사 기록에 남깁니다.

LLM·학습형 분류기는 실행하지 않습니다. 30분 위험도는 민감·대량·비정상 요청의 시간 감쇠 지표이고 자동 권한 부여 점수가 아닙니다. 기본 정책은 운영 이력의 ticket_id/category/status만 100행 이하로 자동 허용합니다.

자동 허용도 에이전트가 별도 execute를 호출해야 조회됩니다. 사람 승인과 범위 승인도 정책 위반을 덮어쓰지 않습니다. 범위 승인의 목적·열·필터는 동일해야 하고 요청 행 수는 원본 이하만 가능합니다.

현재 기본 실행파일은 가상 SQLite 환경이고, PostgreSQL은 [연결 설명서](POSTGRESQL_CONNECTION.md)의 별도 설정입니다. 실제 사내 DB·기업 신원 연동은 수행하지 않았습니다. 기존 대기·승인은 정책 버전이 달라 새 요청으로 제출해야 합니다.
