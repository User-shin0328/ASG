# Local acceptance assessment

**Assessment date:** 2026-10-02

**Result:** Local v1.0 acceptance is **not passed**.
**Scope:** Evidence gathered in the local Windows/Docker Desktop exercise. This is not a production certification. The user's explicit hold on GitHub publication remains in force.

## Decision

The core Gateway boundary, approval integrity, idempotency, audit controls, container isolation checks, recovery cases, dashboard JSON download, bounded resource soak, preregistered L01-L04 matrix, tracked-history scan, full image filesystem scan, six local demos, clean-checkout reproduction, runtime log probe, and real-model one-turn stop test have evidence. Rules scanner v2 measured 42% recall / 4% FPR on a fresh synthetic v6 set, below the 80% recall target; a v5 run reached 80% / 10% only after that set was used for tuning and is diagnostic, not held-out evidence. The optional semantic prefilter met the numeric target on author-created synthetic v4/v5/v6 sets (v6 86% recall / 0% FPR) and is integrated into the host-run Agent adapter as a fail-closed auxiliary check; it never grants permissions. These sets are not independent benchmarks. A real local model run on the assigned adversarial fixture had its text withheld; the Gateway denied the model's report action. The four-arm study used only in-memory tools; baseline attacks all succeeded in that relaxed mock, while policy-only and full had no simulated attack success. All 68 cases are mapped in `docs/case-traceability.md`, with partial and open cases clearly identified. The six approval scenarios used the authenticated dashboard proxy API; the browser approval-button click itself remains unverified. Execution policy remains the security boundary.

## Remaining acceptance gates

1. Preserve v4-v6 as author-created synthetic evaluations only. Rules v2 was tuned using v5, so its v5 result is diagnostic; v6 remains the fresh rule/model evaluation. Do not tune against v6; use an independently authored benchmark or a new preregistered set before generalization claims.
2. Exercise the dashboard approval-button click path; reviewer approval through the authenticated dashboard proxy endpoint and the audit-export interaction are verified, but direct UI interaction is not. The Windows computer-use app launch timed out awaiting its tool approval. L01-L04 remains a separate synthetic study whose policy arms are virtual, not actual Gateway decisions.
3. Keep longer-duration resource and production-capacity qualification open. The configured input boundaries passed a 180-second local soak.
4. Remote GitHub Actions execution remains pending because the user has held publication and no remote is configured.
5. Close the partial and open cases in [traceability](case-traceability.md), develop a dashboard egress control that preserves host access, then re-run the acceptance table. A normal internal bridge and an internal bridge with `gateway_mode_ipv4=isolated` both blocked public TCP egress but also made the published dashboard port unreachable from Windows; a no-masquerade bridge still allowed public TCP. All probes were reverted. The source plan's security and evaluation thresholds are not waived.
6. Stage 18 requires GitHub publication and a matching release tag. It remains on hold per the user's instruction and requires a later explicit go-ahead.

## Honest status

This repository is an implemented local reference MVP with substantial passing evidence, but it is **not project-complete under the plan's acceptance definition**. E04, R04, and R05 remain partial; deterministic rules v2 missed its v6 recall target; and dashboard egress is not restricted. Do not label this state v1.0 or publish a release. GitHub publication and release remain on hold as requested.
