# 현재 게이트웨이 구조

사내 에이전트 → 인증·서버 소유 신원 → 정책 기반 DB 분석 → 자동 허용 / 예외 검토 / 자동 차단 → 실행 직전 검증·누적 예산 예약 → 보호 DB 조회 → 실제 반환량 정산 → 감사 기록.

게이트웨이는 LLM이나 학습형 분류기를 실행하지 않습니다. 요청자는 구조화된 API를 호출하는 일반 프로그램 또는 외부 AI 에이전트일 수 있습니다. 권한은 모델 출력이나 자연어 목적에 의해서 생성되지 않습니다.

DB 정책은 `config/db_access.json`, 기본 도구 정책은 `config/policy.yaml`입니다. 명시적인 운영 이력 기본 열·등록 역할·작업·100행 이하 조건에만 자동 허용하며, 나머지 유효한 요청은 검토합니다. 위반·분석 오류는 차단합니다.

반복 승인은 신원·역할·작업·테넌트·대상·데이터·열·필터·목적·요청당 행 수에 묶이고, 기간·실행 횟수·총 행 수를 제한합니다. 발급 원본 요청도 한도에 포함합니다. 취소·만료·정책 변경은 기존 승인 재사용을 거부합니다.

누적 예산은 원자적으로 최대 요청량을 예약하고 영수증의 실제 반환량으로 정산합니다. 완료 건의 30분 창은 확인 시점부터 계산합니다. 미확정 예약은 자동 환급하지 않습니다. 승인 만료 뒤에도 검토자는 이미 저장된 영수증만 대조할 수 있으며 새로운 SQL은 실행하거나 결과 행을 받지 않습니다.

PostgreSQL은 독립 게이트웨이 연결의 principal별 advisory lock과 감사 체인의 transaction advisory lock으로 경쟁을 통제합니다. 단일 프로세스 SQLite는 RLock과 트랜잭션을 사용합니다. 고가용성·운영 처리량·기업 IdP·운영망 인증서/격리는 별도 검증 범위입니다.

현재 구현 및 검증: [설계계획서](POLICY_GATEWAY_IMPLEMENTATION_PLAN.md). 과거 모델 실험·구조 문서의 수치는 현재 규칙 기반 DB 기능의 성능 근거가 아닙니다.
