# Architecture

The request path is `demo-agent → Gateway → tool-sandbox`. Only the Gateway joins the agent and tool networks. The demo client cannot address the tool sandbox directly. The Gateway, tool sandbox, agent, and dashboard-to-Gateway admin path use internal Docker networks. The dashboard also joins a separate host-facing bridge so Docker Desktop can publish its UI on `127.0.0.1:18501`; its entrypoint installs an nftables default-drop output chain before binding the UI, allowing only loopback, established replies, Docker DNS, and the resolved Gateway IPv4 address on TCP 8000. The Gateway API and tool sandbox are not published to the host. The dashboard forwards a caller-supplied reviewer bearer token to the Gateway and has no embedded reviewer secret. The host-run model adapter can optionally combine its local semantic prefilter with a frozen, integrity-checked n-gram detector; either verdict may withhold untrusted text, while Gateway policy remains the only tool-authorization boundary.

The Gateway authenticates opaque tokens by SHA-256 lookup and derives principal, role, task, user, and tenant from server-owned mappings. It never trusts those fields in an action request. The policy decision is separate from execution state. The Gateway persists actions, approvals, inspections, and audit entries in PostgreSQL. A restricted `gateway_app` role can update action/approval state but can only select and insert audit entries; PostgreSQL triggers also reject audit update, delete, and truncate. The demo tool service repeats task, tenant, owner, and destination checks, then atomically stores simulated side effects and an execution receipt in SQLite.

`send_report` binds approval to a canonical JSON hash of the principal, task, tool arguments, artifact content hash, and policy version. Approval expires after 15 minutes, is scoped to a reviewer tenant, and is consumed before tool execution. Repeated idempotency keys return the original action; a different request under the same key is a conflict. The tool sandbox also returns the same receipt for a repeated execution ID. Policy v2 bounds each agent to 5,000 new actions per rolling 60 seconds and five pending/approved submissions; budget checks serialize across Gateway processes and return 429 before inserting an action or creating a side effect.

PostgreSQL migrations run as a one-shot Compose service before Gateway startup. PostgreSQL advisory locks serialize matching idempotency keys across Gateway processes; approval consumption uses a row lock. Two isolated stress rounds each sent 100 concurrent identical action requests through 32 workers to two Gateway containers: all 200 requests returned HTTP 200, and each round resolved to one action and one receipt. A separate two-Gateway burst sent 50 unique idempotency keys through 25 workers; it produced 50 unique actions and receipts. F01-F06 exercised database unavailability, lost tool responses, Gateway restart during execution, invalid policy, log controls, and audit immutability. The SQLite adapter remains for isolated deterministic unit tests. These bounded single-host tests do not qualify production or multi-host capacity. The hybrid detector has external split evidence, with local distribution limits documented; full plan acceptance remains incomplete while R04 is partial. See `evaluation/results/multiprocess-idempotency-2026-10-02.json`, `evaluation/results/multiprocess-multikey-2026-10-02.json`, and `docs/evaluation-report.md`.

All sample data and report delivery are fictional and local. There is no arbitrary URL, shell, SQL, email, firewall, or external network tool. Four exploratory runs used the locally installed `qwen2.5-coder:7b` model; each unapproved `send_report` call was denied by Gateway policy. This is not a formal model evaluation. The dashboard needs a host-facing bridge for Docker Desktop port forwarding, so its network namespace installs a default-drop nftables output filter before the app starts. The filter allows only loopback, established replies, Docker's local DNS resolver, and the resolved Gateway IPv4 address on TCP 8000. Startup fails closed if the firewall cannot be installed or the Gateway cannot be resolved. The entrypoint drops the capability bounding set and runs the app as UID 10003. Local egress evidence and its limits are recorded in `evaluation/results/dashboard-egress-2026-10-02.json`.
