# 정책 기반 DB 접근 게이트웨이 설계·구현 계획

작성·검증: 2026-11-03 / 기준 커밋: 089385d / 상태: 구현·검증 완료, GitHub 푸시 준비

## 1. 목표와 범위

내부 LLM·Ollama·의미 분류기·학습형 n-gram 실행 경로와 관련 모델 자산을 제거합니다. 외부 요청자는 구조화된 API를 호출하는 일반 프로그램 또는 AI 에이전트일 수 있지만, 게이트웨이는 모델을 실행하지 않습니다. 기존 실험 증거는 과거 결과임을 표시하고 현재 기능·성능 주장에 사용하지 않습니다.

정책 기반 자동 허용, 예외 검토, 제한된 반복 업무 승인, 누적 조회량 통제를 구현합니다. 기존 PostgreSQL·SQLite 검증 DB, 감사 이력, 실행 영수증과 사용자 데이터는 보존합니다. 이번 요청은 GitHub **푸시 준비**이므로 실제 푸시는 수행하지 않습니다.

## 2. 결정 순서

1. 인증·서버 소유 역할/테넌트/작업·정확한 요청 형식·카탈로그 검증.
2. 정책 위반·분석 실패·과도한 요청 빈도는 자동 차단. 사람이 덮어쓸 수 없음.
3. 새 이상 징후가 없고, 일치하는 유효 범위 승인이 있으면 해당 승인으로 허용.
4. 그렇지 않고 명시적 자동 허용 정책에 부합하면 자동 허용.
5. 나머지 유효 요청만 비동기 승인 대기로 저장. 만료는 차단이며 자동 승인하지 않음.

기본 자동 허용은 등록된 운영 이력의 ticket_id/category/status 열, 등록 역할·작업, 요청당 100행 이하로 제한합니다. description 자유문장·연락처·급여·계좌·대량 조회 등은 자동 허용하지 않습니다. 점수만으로 권한을 부여하지 않습니다.

## 3. 범위 승인

검토자는 대기 요청을 일회 승인하거나 반복 업무 범위를 승인합니다. 범위는 요청자의 신원·역할·테넌트·작업·DB 대상·데이터·열·필터·목적과 요청당 최대 행 수에 묶습니다. 다른 목적·필터·열·주체로 확대하지 않습니다.

기간 최대 1시간, 최대 100회, 총 10,000행 안에서 검토자가 한도를 정합니다. 기본 UI 제안은 10분·20회·2,000행입니다. 원래 요청도 횟수·행 수 한도에 포함합니다. 정책 변경·만료·취소·한도 소진 시 재사용을 거부합니다. 취소와 발급은 감사 기록에 남깁니다.

## 4. 누적 예산과 장애 처리

신원별 최근 30분 기본 한도는 1,000회·5,000행입니다. 정책 파일에서 조정하며 실제 운영값으로 확정한 수치는 아닙니다. 실행 전에 요청 최대 행 수를 원자적으로 예약하고 성공 영수증의 실제 반환량으로 정산합니다. 여러 게이트웨이의 경쟁도 PostgreSQL advisory lock으로 직렬화합니다.

같은 실행 ID의 재시도·영수증 재사용은 이중 차감하지 않습니다. 응답 유실·실행 결과 불명은 예약을 유지하며, 미확정 예약은 30분이 지나도 자동 환급하지 않습니다. 실제 SQL 실행은 같은 도구 영수증을 재사용합니다. 성공 캐시를 반환하기 전에도 현재 권한·정책·승인 유효성을 확인합니다.

이 한도는 DB 조회 실행의 반환 행 수를 계량하며, 네트워크 바이트·고유 레코드·모든 데이터 유출을 측정하는 DLP 기능은 아닙니다.

## 5. 저장소·API·화면

- 기존 요청/감사 테이블은 유지. 승인 방식·자동 정책 ID·범위 승인 ID를 요청 열과 분석/승인 메타데이터에 보존.
- 새 범위 승인 테이블과 실행별 예산 원장을 마이그레이션으로 추가.
- 요청 접수: 자동 허용 200 / 검토 필요 202 / 정책 위반 403.
- 범위 승인 발급: 기존 decision API에 선택적 범위 필드 추가. 발급된 승인은 별도 목록·취소 API 제공.
- 대시보드: 자동 허용·사람 승인·범위 승인을 구분, 승인 검토에서 반복 범위 설정, 승인 목록·취소, 신원별 누적 사용량 표시.
- 어두운 배경·흰 글씨·청록색 구분선과 기존 네 페이지를 유지. Impeccable·테이스트스킬의 기존 Operate 화면 규칙 적용.

## 6. 구현 순서와 합격 기준

| 단계 | 작업 | 합격 기준 |
|---|---|---|
| A | LLM 실행 코드·모델·관련 테스트/평가 실행기 제거, 문서 정합화 | 실행 코드에서 모델 호출·관련 import 없음 |
| B | 명시적 자동 허용·예외 분류 정책 | 정상 200, 예외 202, 위반 403 |
| C | 범위 승인 발급·일치 검사·만료·취소 | 신원/열/필터/목적/정책 변경·취소 우회 불가 |
| D | 누적 예산 예약·정산·재시도 | 소량 반복·동시 요청도 한도 초과 불가, 재시도 이중 차감 없음 |
| E | API·대시보드·클라이언트 연동 | 승인 방식과 남은 한도·취소 결과를 실제 화면에서 확인 |
| F | SQLite·실제 PostgreSQL·실행파일 검증 | 자동 경로, 예외 경로, 장애·재시작·동시성 실제 결과 기록 |
| G | 적용 설명·시험 보고서·푸시 준비 | 테스트 결과·바이너리 해시·변경 목록·비밀 제외 점검, 원격 푸시는 보류 |

전체 처리량이나 운영망 격리를 입증한 것으로 표현하지 않습니다. 기능 정확성과 자동 처리 동작을 먼저 검증하고, 측정한 요청 수·동시성·실행 시간을 보고서에 명시합니다.
